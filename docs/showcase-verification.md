# 공연 탐색 화면 검증 기록

2026-09-18, 로컬 PostgreSQL/Redis 및 React 개발 서버 기준.

## 확인한 문제와 반영

| 진단 | 변경 |
|---|---|
| 추상적인 문구만 있는 히어로 | DB 공연·포스터·일정·상세 예매 진입으로 교체 |
| 텍스트 목록으로 공연 구분이 어려움 | 2:3 포스터, 장르, 아티스트, 장소, 일정, 최저 가격 표시 |
| 검색 안내와 달리 제목만 검색 | QueryDSL 제목 OR 아티스트 검색, 장르 조건과 페이지 처리 |
| 회차 전체가 한꺼번에 노출 | 회차 선택 후 해당 재고 표시, 예정 판매 차단 |
| 화면 요청 502 | 로컬 백엔드 실행 후 실제 API 연동 확인 |
| 검증 중 발견한 좁은 화면 넘침·포커스 복귀 누락 | body 최소 폭 해제, 상세 열기 버튼의 로딩 중 포커스 유지 |

## 자동 검증

- 프론트엔드 테스트 7개 통과, TypeScript 및 Vite 프로덕션 빌드 통과.
- 기존 공개 검색 통합 테스트 확장: 비공개 공연 제외, 제목·아티스트 검색, 장르 조합, 일정/가격 집계 확인.
- 공개 상세 캐시 실패 테스트 통과.
- 추가 다중 회차 집계 통합 테스트 통과: 여러 재고의 최저 가격, 여러 공연장 안내, 회차 없는 공연, 페이지 중복 방지.
- 공개 목록 테스트의 SQL 실행 횟수는 3회(목록·개수·페이지 집계). 기존 상세 조회는 2회 유지. 부하 성능 개선 수치를 주장하지 않는다.

## 실제 브라우저 검증

- 320/390px 모바일, 768px 태블릿, 1440px 데스크톱 화면 확인. 320px에서 가로 넘침 발견 후 수정 및 재확인. 이미지 누락 없음.
- 아티스트 '서하' 검색 결과 2개, 공개방송과 조합하면 0개, 전체 공연 복귀 확인.
- 모바일 일반 회원가입 → 2회차 선택 → 1매 선점 → 모의 결제 확정 → 내 예약의 동일 공연/회차/가격 확인 → 취소.
- 데모 데이터 재실행 후 공연 6개·회차 12개·티켓 24개 유지. 선점 중 재고 총합 1539, 취소 후 1540으로 복구. 기존 데이터 삭제 없음.
- 상세·로그인 창의 초기 포커스, Shift+Tab 순환, Escape 닫기, 열었던 버튼으로 포커스 복귀 확인.
- 핵심 색 대비: 주요 버튼 흰 글씨 6.02:1, 기본 보조 글씨 5.26:1, 히어로 보조 글씨 4.74:1. 전체 접근성 인증이나 스크린리더 전수 검증은 아님.
- 자동 재생 없음. 기존 prefers-reduced-motion 규칙 유지.

## 범위와 후속 정보

기존 인증·예약·대기열·모의 결제·취소·운영 콘솔과 정책 경로를 유지한다. 대기열의 실제 혼잡 부하는 이번 화면 작업에서 다시 실행하지 않았다. 데모는 비지정석 기반이며 지정 좌석 선택이나 실제 PG 결제가 추가된 것은 아니다. 실제 운영 사업자 정보와 개인정보 처리방침의 입력 필요 항목은 여전히 운영자 확인이 필요하다.

생성 이미지와 프롬프트 출처는 `showcase-assets.md`, 재현 명령은 `demo-guide.md`를 참고한다. 개인 환경 경로, 인증 토큰, 테스트 계정 입력값과 브라우저 캡처는 커밋 대상에서 제외한다.
