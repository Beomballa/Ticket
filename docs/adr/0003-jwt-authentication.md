# ADR-0003: JWT 기반 인증과 역할 인가

- 상태: 승인
- 결정일: 2026-09-10

## 맥락

예약 API는 로그인 회원을 식별해야 하고, 카탈로그 관리 API는 일반 회원과 관리자를 구분해야 한다.
초기 구현의 HTTP Basic은 자격 증명을 매 요청에 전달하고 서버 간 확장 경계를 표현하기 어렵다.

## 결정

- 이메일과 비밀번호로 회원가입·로그인하며 이메일은 소문자로 정규화한다.
- 비밀번호 원문은 저장하지 않고 BCrypt 해시만 저장한다.
- 로그인 성공 시 30분 유효한 HS256 Access Token을 발급한다.
- JWT subject는 회원 ID, `roles` claim은 `USER` 또는 `ADMIN`을 담는다.
- 서버는 세션을 만들지 않고 Spring Security Resource Server로 서명, 발급자와 만료를 검증한다.
- `/api/admin/**`는 `ADMIN` 역할만 허용하고 나머지 보호 API는 인증된 회원에게 허용한다.
- 로그인 실패 응답은 이메일 존재 여부와 무관하게 동일하게 반환한다.

## 결과

서버 인스턴스 간 세션 공유 없이 인증을 검증할 수 있고 역할 인가 규칙이 Security Filter Chain에
집중된다. 대칭키를 사용하는 동안 모든 검증 서버가 서명 키를 공유하므로 운영 환경에서는 키를
비밀 저장소에서 주입하고 주기적으로 교체해야 한다. 외부 인증 서버나 다중 서비스로 확장할 때는
RSA 또는 EC 비대칭키와 공개키 배포 방식으로 전환한다.
