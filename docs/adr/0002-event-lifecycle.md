# ADR-0002: 이벤트 생성과 판매 상태 전이를 분리한다

- 상태: 승인
- 결정일: 2026-09-09

## 배경

생성 API가 임의의 상태를 받으면 검수되지 않은 이벤트가 바로 판매 상태로 만들어지고, 상태별 수정 제한도 우회할 수 있다. 회차와 재고 변경이 예약과 동시에 발생하면 금액·수량 정합성도 깨질 수 있다.

## 결정

- 이벤트는 항상 `DRAFT`로 생성한다.
- 상태 변경은 전용 API와 도메인 메서드로만 수행한다.
- 허용 전이는 `DRAFT → PUBLISHED → ON_SALE → CLOSED`다.
- `DRAFT`, `PUBLISHED`, `ON_SALE`은 `CANCELLED`로 종료할 수 있다.
- 동일 상태 요청은 멱등하게 성공한다.
- 역방향 전이와 종단 상태 변경은 거부한다.
- 이벤트·회차·판매 재고 정보는 `DRAFT`와 `PUBLISHED`에서만 수정한다.
- `ON_SALE` 이후 재고 증감은 카탈로그 수정과 분리해 향후 재고 조정 명령과 감사 로그로 구현한다.

## 결과

- 생성과 공개·판매 승인이 명확히 분리된다.
- 판매 중 수량을 단순 덮어쓰는 경로가 차단된다.
- 향후 예약 재고 차감과 관리자 재고 조정의 책임을 별도로 설계할 수 있다.
- 운영자가 잘못된 전이를 요청하면 HTTP 409와 `INVALID_STATE_TRANSITION` 오류를 받는다.
