# ADR-0005: 예약 확정·취소와 모의 결제 경계

> 결제 승인 응답 유실과 운영 대사 결정은 [ADR-0018](0018-payment-attempt-reconciliation.md)에서 확장한다.

- 상태: 승인
- 결정일: 2026-09-11

## 맥락

선점된 예약은 결제 성공 후에만 확정되어야 하며 취소 시 선점 재고를 정확히 한 번 반환해야 한다.
확정 전 취소에는 환불이 없지만 확정 후 취소에는 환불 절차가 필요하다. MVP에서는 실제 PG를
연결하지 않으면서도 이 경계와 실패 흐름을 테스트할 수 있어야 한다.

## 결정

- 애플리케이션 계층은 `PaymentGateway` 포트에만 의존하고 MVP 구현은 `MockPaymentGateway`로 둔다.
- `mock-approved` 토큰만 승인을 성공시키며 다른 토큰은 `PAYMENT_DECLINED` 오류를 반환한다.
- `PENDING` 예약은 만료 전 승인 성공 시 `CONFIRMED`로 전이한다.
- 승인 실패 시 트랜잭션을 롤백해 예약은 `PENDING`, 재고는 선점 상태로 유지한다.
- `PENDING` 취소는 결제 호출 없이 재고를 반환하고 `CANCELLED`로 전이한다.
- `CONFIRMED` 취소는 모의 환불 성공 후 재고를 반환하고 `CANCELLED`로 전이한다.
- 이미 확정·취소된 예약에 같은 명령을 순차 반복하면 외부 호출과 재고 변경을 다시 수행하지 않는다.
- 예약 소유 회원만 확정·취소할 수 있으며 다른 회원에게는 예약 존재 여부를 노출하지 않는다.

## 결과와 남은 위험

도메인 상태 전이, 결제 경계와 재고 반환을 자동 테스트로 재현할 수 있다. 다만 실제 PG는 DB
트랜잭션에 참여하지 않으므로 다음 위험이 남는다.

- 승인 성공 후 DB 커밋 실패 시 결제와 예약 상태가 어긋날 수 있다.
- 멱등키가 적용되기 전 동시 확정 요청은 외부 승인을 중복 호출할 수 있다.
- 실제 환불 실패는 비동기 재시도와 운영 대사 대상이 되어야 한다.

예약 생성·확정 멱등키는 다음 동시성·멱등성 작업에서 추가한다. 실결제 전환 시 PG 멱등키,
결제 시도 저장, Transactional Outbox, 재시도와 대사 작업을 함께 설계한다.
