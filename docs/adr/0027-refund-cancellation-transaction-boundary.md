# ADR-0027: 환불 취소의 순차 트랜잭션 경계와 원자 원장 claim

- 상태: 승인
- 결정일: 2026-09-16

## 맥락

확정 예약 취소는 하나의 외부 트랜잭션이 예약과 재고를 읽은 뒤 `REQUIRES_NEW`로 환불 원장을
생성하고 PG 환불 응답까지 기다렸다. 동시 요청이 Hikari 최대 연결 수에 도달하면 각 요청이 이미
점유한 연결을 놓지 않은 채 원장 트랜잭션의 두 번째 연결을 기다릴 수 있다. 또한 같은 예약의 동시
취소는 조회 후 INSERT 사이에서 유니크 충돌을 노출하고, 후속 요청이 실제 처리 중인 `REQUESTED`를
즉시 `UNKNOWN`으로 바꾸는 경쟁이 있었다.

## 결정

- 예약 소유권·취소 가능 상태·금액은 짧은 읽기 트랜잭션에서 검증하고 스냅샷으로 반환한다.
- 일반 취소 환불 원장은 `INSERT ... ON CONFLICT DO NOTHING`으로 원자 생성한다.
- 삽입 충돌 시 예약별 기존 원장을 다시 읽고 금액과 상태를 검증한다.
- 기본 30초 처리 유예시간 안의 `REQUESTED`는 상태를 바꾸지 않고
  `409 IDEMPOTENCY_REQUEST_IN_PROGRESS`로 응답한다.
- 유예시간이 지난 `REQUESTED`만 `UNKNOWN`과 즉시 자동 대사 대상으로 전환한다.
- PG 환불 호출은 Spring DB 트랜잭션이 없는 상태에서 실행하고 성공·거절·결과 불명은 각각
  독립 트랜잭션으로 기록한다.
- 마지막 취소 트랜잭션은 예약 행을 `FOR UPDATE`로 잠근 뒤 예약 취소·재고 반환·Outbox를 함께
  커밋한다. 뒤따른 요청은 잠금 획득 후 `CANCELLED`를 확인해 부작용을 반복하지 않는다.
- claim 결과는 `created`, `in_progress`, `recovered_unknown`, `reused` counter로 관측한다.

## 결과

각 취소 단계는 동시에 최대 하나의 DB 연결만 사용하며 PG 응답 중에는 연결을 점유하지 않는다.
같은 예약의 취소가 동시에 도착해도 환불 원장은 한 건이고 PG 환불, 재고 반환과 취소 Outbox는
각각 한 번만 실행된다. 프로세스가 원장 기록 뒤 중단되면 처리 유예시간 후 기존 UNKNOWN 자동
대사 경로로 수렴한다.

## 운영 고려사항

`in_progress`의 짧은 증가는 사용자 중복 클릭이나 네트워크 재시도로 정상 발생할 수 있다.
`recovered_unknown`이 급증하면 PG 장기 지연, 프로세스 중단 또는 환불 결과 기록 실패를 확인한다.
예약별 환불 원장 유일 제약은 기존 스키마에 있으므로 추가 마이그레이션은 필요하지 않다. 실제 PG
연동 시에는 환불 처리시간 분포를 측정해 30초 유예시간을 조정한다.
