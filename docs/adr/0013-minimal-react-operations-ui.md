# ADR-0013: 백엔드 시연을 위한 최소 React 운영 UI

## 상태

채택

## 맥락

이 프로젝트의 평가 대상은 재고 동시성, 멱등성, QueryDSL 읽기 모델, Outbox와 운영 관측성이다. 하지만 API 문서만으로는 제3자가 사용자 예약 흐름과 관리자 조회 결과를 짧은 시간에 연결해서 보기 어렵다. 프론트엔드에 과도한 시간을 쓰면 백엔드 의사결정의 근거가 흐려진다.

## 결정

- React와 TypeScript로 사용자 이벤트 탐색, 로그인, 재고 선점, 모의 결제 확정·취소를 제공한다.
- 관리자 화면은 QueryDSL 조회 API의 예약 집계, 최근 예약, 재고 현황에 집중한다.
- 별도 UI 라이브러리 없이 CSS custom property로 색상, 여백, 반경을 관리한다.
- 프론트 개발 서버가 `/api`와 `/actuator`를 Spring Boot로 프록시한다. 운영 배포 시에는 같은 origin reverse proxy를 권장한다.
- 인증 토큰은 포트폴리오 데모의 단순성을 위해 `localStorage`에 둔다. 실제 서비스에서는 BFF 또는 HttpOnly Secure cookie를 우선 검토한다.
- 화면은 API 오류의 `traceId`를 노출해 Grafana와 애플리케이션 로그로 이어지는 장애 분석 흐름을 보여준다.

## 대안

- 서버 사이드 템플릿은 배포가 단순하지만 사용자·관리자 상태 전환과 API 계약 시연이 불편하다.
- 대형 컴포넌트 라이브러리는 구현 속도를 높일 수 있지만 결과물의 비중과 번들 크기를 불필요하게 키운다.
- 토큰을 메모리에만 두면 XSS 노출 범위는 줄지만 새로고침 때마다 다시 로그인해야 해 로컬 데모가 불편하다.

## 결과

제3자는 두 개의 실행 명령과 데모 데이터 한 번으로 핵심 흐름을 시연할 수 있다. 프론트는 백엔드 API 계약을 소비하는 얇은 계층으로 유지된다. 인증 저장 방식과 별도 origin CORS 정책은 운영 전환 시 반드시 재설계해야 한다.
