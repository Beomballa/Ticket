# ADR-0021: 서명 검증 PG 웹훅 Inbox와 멱등 처리

## 상태

채택

## 맥락

조회 기반 자동 대사는 PG 응답 유실을 복구하지만 다음 polling 시각까지 지연되고 반복 조회 비용이 든다. PG 웹훅은 같은 이벤트를 재전송하거나 순서가 바뀔 수 있고, 위조 요청·오래된 요청·같은 이벤트 ID의 다른 본문도 구분해야 한다. 외부 호출 직후 애플리케이션이 중단되더라도 수신 사실과 실패 원인이 남아야 한다.

## 결정

- 모의 PG는 `X-PG-Timestamp`와 원문 body를 `timestamp.body`로 결합해 HMAC-SHA256 서명을 만들고 `X-PG-Signature`로 전달한다. 서버는 원문을 JSON으로 변환하기 전에 constant-time 비교로 검증하며 기본 허용 시차는 5분이다.
- 서명을 통과한 이벤트만 `payment_webhook_inbox`에 저장한다. PG event ID를 유일키로 사용하고 본문 SHA-256이 같은 재전달은 멱등 성공, 다른 본문은 `409 WEBHOOK_EVENT_CONFLICT`로 처리한다.
- Inbox 상태는 `RECEIVED → PROCESSING → PROCESSED|FAILED`로 전이한다. 선점은 만료 가능한 30초 임대와 시도 번호를 원자적으로 갱신하며, 완료 갱신에도 시도 번호를 조건으로 사용해 임대가 회수된 이전 작업자의 늦은 완료가 새 작업을 덮지 못하게 한다.
- 결제·환불 결과는 기존 관리자 대사 서비스를 호출해 예약·재고·Outbox·감사 로그의 정합성 경계를 공유한다. 웹훅 누락은 기존 자동 조회 대사가 계속 복구한다.
- 운영자는 QueryDSL projection 목록에서 최근 Inbox와 오류를 확인하고 `FAILED` 이벤트만 화면에서 다시 처리한다.

## 구현 선택

Inbox 영속 상태와 기존 원장의 최종 전이는 JPA로 관리하고 운영 목록은 QueryDSL로 조회한다. event ID 중복 삽입과 임대 선점은 경쟁 조건을 한 SQL에서 판정해야 하므로 `INSERT ... ON CONFLICT`와 `UPDATE ... RETURNING`에만 좁게 Native SQL을 사용한다.

## 결과

PG가 결과를 전달하는 즉시 기존 대사 경계로 수렴하며 같은 이벤트의 재전달은 부작용을 늘리지 않는다. 처리 도중 장애는 Inbox의 `FAILED` 상태와 오류로 남고, 프로세스 중단은 임대 만료 후 안전하게 회수된다. 서명 거부·충돌·처리 결과는 Micrometer counter로 구분한다.

## 남은 위험

- 실제 PG별 서명 형식, 키 회전과 IP 정책은 adapter에서 분리해야 한다.
- 예약 만료 뒤 늦게 도착한 승인 결과는 자동 확정하지 않으며 보상 환불 정책이 필요하다.
- Inbox 보관 기간과 개인정보 삭제 정책은 운영 트래픽과 계약 요건을 기준으로 정해야 한다.
