# ADR-0004: 예약 선점 트랜잭션 기준선

- 상태: 승인
- 결정일: 2026-09-11

> 재고 차감의 낙관적 락 기준선은 비교 실험 후 ADR-0007의 조건부 UPDATE 결정으로 대체되었다.

## 맥락

한 예약은 여러 판매 재고를 포함할 수 있다. 일부 항목만 차감되거나 예약과 재고 변경 중 하나만
저장되면 가용 수량과 주문 기록이 어긋난다. 고경합 환경의 최종 재고 차감 전략은 별도 비교 실험이
필요하지만, 예약 수직 슬라이스에는 먼저 정확한 로컬 트랜잭션 경계가 필요하다.

## 결정

- 인증 회원 조회, 재고 검증·차감, `PENDING` 예약과 항목 저장을 하나의 트랜잭션에서 처리한다.
- 요청 항목은 재고 ID 오름차순으로 처리해 여러 재고 접근 순서를 일관되게 한다.
- 재고 엔티티가 판매 상태·판매 시간·가용 수량 불변식을 검사하고 음수 차감을 거부한다.
- 예약 항목에는 요청 당시 단가를 스냅샷으로 보관하며 총액은 스냅샷 단가로 계산한다.
- 선점 만료 시간은 설정 가능한 10분을 초기 기준값으로 사용한다.
- 현재 동시 수정 감지는 기존 JPA `@Version` 낙관적 락을 사용하고 충돌은 재시도 가능한 409로 반환한다.

## 대안과 후속 결정

- 비관적 락은 구현이 단순하지만 대기 시간과 교착 위험을 측정해야 한다.
- 조건부 `UPDATE ... WHERE available_quantity >= ?`는 원자적 차감에 유리하지만 JPA 영속성 컨텍스트와
  벌크 갱신 처리 기준이 필요하다.
- 낙관적 락, 비관적 락, 조건부 UPDATE의 최종 선택은 3단계에서 동일한 동시 요청 시나리오와
  처리량·충돌률·p95·DB 부하를 측정한 뒤 별도 ADR로 확정한다.
- 멱등키 저장과 중복 응답 재사용은 후속 작업에서 예약 생성 계약에 추가한다.

## 결과

중간 항목의 재고 부족 또는 예외 발생 시 앞선 재고 차감과 예약·항목 INSERT가 함께 롤백된다.
현재 기준선은 정확한 트랜잭션 경계를 제공하지만, 고경합 상황의 성공률과 지연 시간은 아직
검증하지 않았으므로 운영 전략으로 확정하지 않는다.
