# ADR-0007: 고경합 재고 차감 전략

- 상태: 승인
- 결정일: 2026-09-11
- 대체 대상: ADR-0004의 재고 차감 낙관적 락 기준선

## 맥락

티켓 오픈 시 하나의 재고 행에 요청이 집중된다. 재고는 절대 음수가 되어서는 안 되며, 충돌을
처리하기 위한 애플리케이션 재시도와 DB 잠금 대기가 응답 지연을 과도하게 높이지 않아야 한다.
낙관적 락, 비관적 락과 조건부 UPDATE를 PostgreSQL에서 같은 재고와 부하로 비교했다.

## 결정

예약 생성의 재고 차감에는 다음 조건을 포함한 원자적 UPDATE를 사용한다.

```sql
UPDATE sellable_inventory
SET available_quantity = available_quantity - :quantity,
    version = version + 1,
    updated_at = CURRENT_TIMESTAMP
WHERE id = :inventoryId
  AND available_quantity >= :quantity
```

- 영향받은 행이 1개이면 차감 성공, 0개이면 재고 부족으로 판정한다.
- 여러 재고는 ID 순으로 차감하고 예약 저장과 같은 트랜잭션에 포함한다. 중간 실패 시 이전
  차감도 함께 롤백한다.
- 조건부 UPDATE 뒤 JPA 엔티티를 조회해 판매 상태와 가격 스냅샷을 검증·저장한다.
- `version`을 함께 증가시켜 취소·관리 작업 등 기존 JPA 낙관적 락 경로와 일관성을 유지한다.
- Native SQL은 이 원자적 재고 차감 경로에만 한정하고 나머지 쓰기 모델은 JPA를 유지한다.

## 비교 근거

재고 100, 요청 1,000, 작업 스레드 32, HikariCP 연결 10의 로컬 Testcontainers 기준선에서 세
전략 모두 성공 100건과 최종 재고 0으로 초과 판매가 없었다.

- 낙관적 락: 2,963.86 TPS, p95 32.12ms, 충돌 549건(54.90%)
- 비관적 락: 2,476.35 TPS, p95 39.05ms, 충돌 0건
- 조건부 UPDATE: 7,105.08 TPS, p95 15.97ms, 충돌 0건

조건부 UPDATE는 한 문장으로 수량 검사와 차감을 끝내며, 측정 기준선에서 가장 높은 처리량과
가장 낮은 p95를 보였다. 트랜잭션 제어문을 제외한 SQL도 낙관적 락 1,649회, 비관적 락
1,100회, 조건부 UPDATE 1,000회로 가장 적었다. 상세 조건과 해석은 재고 잠금 전략 비교 실험
문서에 기록한다.

## 결과와 남은 위험

고경합 행에서 애플리케이션 재시도 없이 초과 판매를 방지하고 재고 부족을 명확히 구분한다.
다만 단일 행 갱신 잠금 자체는 존재하므로 DB 연결 수를 무작정 늘리면 대기열과 커넥션 고갈이
발생할 수 있다. 여러 재고를 포함하는 예약은 ID 순서를 유지해야 교착 가능성을 줄일 수 있다.
또한 로컬 단일 실행 수치는 상대 비교 기준이며 운영 용량을 보장하지 않는다. 실제 배포 환경에서
충돌률, DB lock wait, 커넥션 풀 대기와 p95를 다시 측정해야 한다.
